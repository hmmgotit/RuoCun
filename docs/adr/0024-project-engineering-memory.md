# ADR-0024　按工作区发布工程摘录，发送请求前复核权限与版本

2026-11-27 · 从 v2.3.0 起采用 · 承接 ADR-0005、ADR-0020、ADR-0021。记忆实现来自 `2.2.0+memory.2`。最终实测以正式 v2.2.0 作对照。技术交付与模型效果分别记录。

## 决定

会话归档继续保存原文、工具调用及来源链。项目工程库保存用户授权共享的脱敏短摘录，键由账户中的实际工作区与主会话原始来源共同确定。每条记录只有一个有效版本。同一位置的 Git 分支共享身份，各工作区需单独开启工程积累。引用方向、单条发布及源版本均在读取时裁决。写入、版本更新、撤回和配额裁剪在同一 SQLite 事务中确认。

原生 Markdown 继续管理已有规则、锁定项及兼容来源。自动捕获的用户工程约定与其跨会话出处一起保存，以同一身份进入稳定启动选择与主动查阅。重复补录、子代理转述和迟到的受控提炼复用该身份。手动读取和自动召回均按当前源码检查原先的证据。关键词、代码符号与可选本地语义检索共用任务额度。向量配置以工作区为界，索引可从当前有效记录重建。

模型请求使用当前授权的投影。条目撤回或版本改变时，舍弃可追溯的旧片段，同时保留工具消息配对。混合摘要和归档分页保存参与生成的身份与版本，任一来源失效即省略整个派生块。用户输入和历史归档保持各自的原生命周期。这个例外允许撤回时中断前缀缓存复用。模型使用的真实证据以本次工具结果为准。

## 验收

在隔离的用户目录和工作区中从普通 CLI 验证全新安装与旧版升级。保留候选的模型评测结果，按发行验证决定是否发布。[操作说明](../memory-design.md) · [盲题结果](../../CHANGELOG.md#230)
